# tg_playlist_bot

بات تلگرام برای ساخت پلی‌لیست از موزیک‌های یک کانال: موزیک‌های کانال اصلی رو با اسم خواننده، اسم آهنگ و هشتگ‌ها ایندکس می‌کنه، با یک جست‌وجو (مثلاً `ebi` یا `#remix`) نتایج رو نشون می‌ده و با یک دکمه همه‌شون رو داخل یک کانال دیگه می‌ریزه. دفعه‌ی بعد، پلی‌لیست قبلی اول پاک می‌شه.

Python 3.12 · [python-telegram-bot](https://github.com/python-telegram-bot/python-telegram-bot) · SQLite · Docker

## چطور کار می‌کنه

```
کانال اصلی ──(channel_post / edited_channel_post)──▶ بات ──▶ SQLite (اسم، خواننده، هشتگ‌ها)
                                                       │
 تو چت خصوصی با بات: «ebi» ─▶ پیش‌نمایش ─▶ [📤 ساخت پلی‌لیست]
                                                       │  1) پیام‌هایی که خود بات قبلاً فرستاده پاک می‌شن
 کانال پلی‌لیست ◀──── copyMessage (بدون «forwarded from») ◀┘  2) نتایج به ترتیب کپی می‌شن
```

* موزیک‌ها **کپی** می‌شن (`copyMessage`)، نه دانلود/آپلود دوباره؛ سریع و بدون مصرف ترافیک سرور.
* بات فقط پیام‌هایی رو از کانال پلی‌لیست پاک می‌کنه که **خودش فرستاده** (شناسه‌هاشون تو دیتابیسه).
* بات با long polling کار می‌کنه: **هیچ پورتی باز نمی‌شه** و نیازی به دامنه/SSL نیست.

### نکته‌ی مهم: تاریخچه‌ی قدیمی
Bot API به بات اجازه‌ی خوندن پیام‌های **قبلی** کانال رو نمی‌ده؛ فقط پست‌های جدید و ویرایش‌ها رو می‌بینه. پس موزیک‌های فعلی (~۲۰۰۰ تا) رو **یک بار** با اکسپورت تلگرام دسکتاپ وارد می‌کنیم (پایین‌تر). از اون به بعد همه‌چیز خودکار آپدیت می‌شه:

* موزیک جدید پست کنی ← اضافه می‌شه
* کپشن/هشتگ ویرایش کنی ← آپدیت می‌شه
* موزیکی رو از کانال پاک کنی ← تلگرام به بات خبر نمی‌ده؛ دفعه‌ی بعدی که تو یک پلی‌لیست بیاد و کپی نشه، خودش از دیتابیس حذف می‌شه.

## راه‌اندازی

۱. از [@BotFather](https://t.me/BotFather) یک بات بساز و توکن رو بردار. (پیشنهاد: `/setjoingroups` رو Disable کن تا کسی نتونه بات رو به گروه اضافه کنه.)

۲. دو کانال داشته باش: **کانال اصلی** (موزیک‌هات) و **کانال پلی‌لیست** (خالی). بات رو ادمین هر دو کن:
   * کانال اصلی: ادمین، بدون هیچ دسترسی اضافه (فقط برای دریافت پست‌ها و کپی کردن).
   * کانال پلی‌لیست: ادمین با **Post messages** و **Delete messages**.

۳. آی‌دی‌ها رو پیدا کن:
   * آی‌دی عددی خودت: [@userinfobot](https://t.me/userinfobot)
   * آی‌دی کانال‌ها (`-100…`): کانال رو از [@RawDataBot](https://t.me/RawDataBot) فوروارد کن، یا تو تلگرام وب آدرس کانال رو ببین (`web.telegram.org/k/#-100…`).

۴. روی Dokploy:
   * پروژه از نوع **Docker Compose** بساز، این ریپو رو وصل کن (Build: `docker-compose.yml`).
   * تو تب Environment این‌ها رو بذار (نمونه: `.env.example`):
     `BOT_TOKEN`, `OWNER_IDS`, `SOURCE_CHANNEL_ID`, `PLAYLIST_CHANNEL_ID`
   * Deploy. دیتابیس تو volume با اسم `bot_data` می‌مونه و با redeploy پاک نمی‌شه.

۵. تو چت خصوصی با بات `/status` بزن؛ دسترسی هر دو کانال رو چک می‌کنه.

### ایمپورت موزیک‌های قدیمی
تلگرام دسکتاپ ← کانال موزیک ← ⋮ ← **Export chat history** ← تیک همه‌ی Media رو بردار ← Format: **JSON** ← Export.

* فایل `result.json` رو (اگه کمتر از ۲۰MB بود، که برای ۲۰۰۰ موزیک بدون مدیا حتماً هست) همون‌جا تو چت بات بفرست.
* یا:
  ```bash
  docker cp result.json <container>:/tmp/result.json
  docker exec <container> python -m app.import_cli /tmp/result.json
  ```

ایمپورت امنه و تکراری‌پذیره: دوباره اجراش کنی چیزی دوبل نمی‌شه، و داده‌ای که بات خودش از کانال گرفته رو با داده‌ی قدیمی‌تر اکسپورت overwrite نمی‌کنه. اگه اکسپورت مال کانال دیگه‌ای باشه رد می‌شه (چون شناسه‌ها اشتباه کپی می‌کردن).

## استفاده

هر متنی که تو چت خصوصی بفرستی یک جست‌وجوئه.

| ورودی | معنی |
|---|---|
| `ebi` | اول‌کلمه‌ی `ebi` تو اسم خواننده، اسم آهنگ، اسم فایل، کپشن یا هشتگ (`Rebirth` رو نمی‌گیره) |
| `#remix` | هشتگ دقیق `#remix` |
| `#remix #rap` | هر دو هشتگ |
| `ebi -#remix` | ebi ولی بدون ریمیکس |
| `artist:ebi` / `title:shab` | فقط تو خواننده / فقط تو اسم آهنگ |
| `"shab bokhor"` | عبارت دقیق |

فارسی/انگلیسی، بزرگ‌کوچک، `ي/ی`، `ك/ک`، اعداد فارسی و نیم‌فاصله نرمال می‌شن. دستورها: `/tags` `/artists` `/stats` `/status` `/clear` `/stop` `/import` `/help`.

## امنیت

* **فقط `OWNER_IDS`**: پیام و دکمه‌ی بقیه کاملاً نادیده گرفته می‌شه (حتی اگه بات رو پیدا کنن).
* فقط پست‌های `SOURCE_CHANNEL_ID` ایندکس می‌شن؛ پست هر کانال دیگه‌ای که بات توش ادمین بشه نادیده گرفته می‌شه. اگه دو کانال یکی باشن، بات اصلاً بالا نمیاد.
* حذف فقط روی پیام‌هایی که خود بات فرستاده؛ هیچ‌وقت چیزی از کانال اصلی پاک نمی‌شه.
* توکن فقط تو env است، تو repr/لاگ نمیاد (لاگ‌های httpx که URL دارن خاموش‌اند + redaction روی همه‌ی لاگ‌ها).
* همه‌ی کوئری‌های SQL پارامتری‌اند؛ متن‌های کاربر/کانال قبل از نمایش HTML-escape می‌شن.
* فایل ایمپورت: فقط از owner، حداکثر ۲۰MB، فقط JSON، بدون اجرای هیچ کدی.
* کانتینر: کاربر غیر root، filesystem فقط‌خواندنی (به‌جز `/data`)، `cap_drop: ALL`، `no-new-privileges`، بدون پورت، محدودیت حافظه.
* دیتابیس فقط متادیتای موزیک‌هاست (اسم/خواننده/کپشن)؛ فایل صوتی و داده‌ی حساس نگه نمی‌داره. برای بکاپ کافیه volume `bot_data` رو کپی کنی.

## توسعه

```
app/config.py     تنظیمات از env (+ اعتبارسنجی)
app/textutil.py   نرمال‌سازی متن/هشتگ (مشترک بین ذخیره و جست‌وجو)
app/models.py     Track
app/db.py         SQLite: schema، migrations (لیست _MIGRATIONS)، upsert، آمار
app/search.py     پارس کوئری ← SQL پارامتری
app/ingest.py     پست زنده + اکسپورت دسکتاپ ← Track
app/playlist.py   پاک‌کردن و پر کردن کانال پلی‌لیست (flood-wait، توقف، رفع حذف‌شده‌ها)
app/bot.py        هندلرهای تلگرام (UI)
app/texts.py      متن‌های فارسی
```

* قابلیت جدید جست‌وجو (مثلاً فیلتر سال/مدت): یک `field` تو `search.py` و یک ستون تو `db.py`.
* مرتب‌سازی دیگر (shuffle، جدیدترین اول): `publish()` ترتیب ورودی رو حفظ می‌کنه؛ فقط لیست `track_ids` رو مرتب کن.
* دستور جدید: یک متد تو `PlaylistBot` + یک خط تو `build()`.

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
python -m pytest
```

## محدودیت‌ها
* ارسال به کانال با فاصله‌ی `SEND_DELAY` (پیش‌فرض ۱ ثانیه) انجام می‌شه تا به flood limit نخوری؛ پلی‌لیست ۳۰۰ تایی ≈ ۵ دقیقه. اگه تلگرام `RetryAfter` بده بات صبر می‌کنه و ادامه می‌ده.
* پاک کردن پیام‌های خیلی قدیمی پلی‌لیست به دسترسی **Delete messages** نیاز داره. اگه پاک نشدن، تو پیام نتیجه گزارش می‌شه.
* هر لحظه فقط یک پلی‌لیست ساخته می‌شه؛ `/stop` اون رو متوقف می‌کنه.
